# 오토브리프 관리자 콘솔 (fleet console)

차에 설치된 오토브리프 앱이 보내는 운행 원장(웹훅)을 받아, 회사 관리자 화면으로 보여주는 시연용 서버입니다.
파이썬 표준 라이브러리만 쓰므로 설치할 것이 없고, Python 3.9 이상이면 macOS, Windows, Linux에서 그대로 실행됩니다.

## 실행

```
python3 fleet_console.py --port 8787 --bind 127.0.0.1 --data ./fleet-data
```

- 관리자 화면: http://127.0.0.1:8787/ (2초마다 자동 갱신)
- 안드로이드 에뮬레이터가 보낼 주소: `http://10.0.2.2:8787/hook` (에뮬레이터의 10.0.2.2는 이 노트북의 127.0.0.1입니다)
- 앱은 http를 10.0.2.2와 127.0.0.1(localhost)에만 보내고, 다른 주소에는 https로만 보냅니다. 실제 단말로 시연하려면
  USB로 연결해 `adb reverse tcp:8787 tcp:8787`을 실행하고 앱의 보내기 주소에 `http://127.0.0.1:8787/hook`을 넣으세요.
  서버에는 인증이 없으므로 `--bind 0.0.0.0`으로 바깥에 열 때는 시연하는 동안만 켜 두세요.
- `--data` 폴더에는 받은 원장과 운행기록부 파일이 쌓입니다. 시연 기록이므로 저장소에 올리지 마세요.

## 주소

| 주소 | 설명 |
| --- | --- |
| `POST /hook` | 원장 항목(`ledger_entry`)과 운행기록부(`logbook_archive`) 수신. `Idempotency-Key` 헤더가 같으면 한 번만 반영 |
| `GET /` | 관리자 화면 |
| `GET /api/state` | 화면이 쓰는 JSON (차량별 상태, 가장 최근 운행이 있는 달과 그 해의 집계, 최근 운행 30건, 보관 파일, 알림) |
| `GET /archives/<파일>` | 보관된 운행기록부 내려받기 |
| `GET /healthz` | 살아 있는지 확인 (`ok`) |

## 원장 체인과 시연 사본

- 앱은 원장을 처음 시작할 때 임의의 `chainId`(영문, 숫자, `-`, `_` 64자 이내)를 만들어 모든 항목에 붙입니다. 콘솔은
  차(차대번호, 없으면 번호판)와 `chainId`를 묶은 `차대번호#chainId` 하나를 원장 사본 하나로 보관합니다.
  `chainId`가 없는 페이로드(앱 2.0.0 이전)는 차 하나에 사본 하나입니다.
- `space`는 `live`(실제 기록) 또는 `demo`(앱의 시연 모드)입니다. 필드가 없으면 실제 기록으로 봅니다. 시연 공간의
  원장은 실제 원장과 따로 쌓이고, 관리자 화면에서 차 번호 아래에 **시연** 표시가 붙습니다(`/api/state`의 `label`).
- 같은 차의 실제 원장이 새 `chainId`로 다시 시작되면(앱 데이터 초기화, 재설치, 또는 누군가 기록을 새로 시작함) 새 원장에
  "원장이 새로 시작되었습니다 (이전 원장 마지막 순번 N): 앱 초기화 또는 위조 가능성" 알림이 붙고 상태는 **누락 있음**이
  됩니다. 이전 원장은 지우지 않고 그대로 둡니다. 시연 원장이 새로 시작될 때는 알리지 않습니다.
- 형식이 맞지 않는 `chainId`나 `space`는 400으로 거절합니다.
- 시연을 처음부터 다시 하려면 앱의 시연 기록을 지우고 콘솔을 끈 뒤 `--data` 폴더를 비우고 다시 켭니다. 폴더를 그대로 두면
  앞 시연의 원장이 남아 있고, 앱의 새 시연 원장은 새 사본(새 `chainId`)으로 쌓입니다.

## 검증 규칙

- 항목마다 해시를 다시 계산합니다. 어긋나면 **변조 의심**.
- 번호(seq)가 건너뛰면 **누락 있음**, 같은 번호에 다른 내용이 오면 **변조 의심**.
- 변조가 의심되면 관리자 화면의 집계 위에 빨간 알림 띠가 뜹니다. 이미 받은 순번에 다른 내용이 오면 그 기록은 반영하지 않고
  (회사 사본은 처음 받은 기록 그대로), 그 순번이 가리키는 운행 줄에 '변조 시도' 표시를 붙입니다.
- 업무 사용 비율 = (출퇴근 + 일반 업무) ÷ 전체 주행거리. 업무 km는 출퇴근과 일반 업무의 합입니다.
- 원장의 운행 본문에 `family: true`가 있으면 가족 운행입니다. 장소 없이 오고, 줄에 "가족 운행 (위치 기록 안 함)"이 붙으며
  비업무로 셉니다(목적 지정 항목이 오기 전에도).
- 내 차 모드의 운행기록부(`logbook_archive`)는 `fuelReimbursement`(달마다 업무 거리, 연비, 유가, 금액)를 함께 보냅니다. 화면은
  그 차 아래에 금액이 있는 가장 최근 달을 "유류비 정산 N원 (YYYY-MM)" 한 줄로 보여 줍니다. 형식이 맞지 않는 값은 무시하고
  파일은 그대로 받습니다.
- 서버를 껐다 켜도 `--data`의 기록을 다시 읽어 같은 화면을 복원합니다.

## 메모리 한도 (코드 상단 상수)

차량 200대, 차량당 원장 50,000건(최신 유지), 운행기록부 100개(오래된 것부터 삭제), 요청 본문 15MB(초과 시 413), Idempotency-Key 차량당 5,000개.
