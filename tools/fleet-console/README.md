# 오토브리프 관리자 콘솔 (fleet console)

차에 설치된 오토브리프 앱이 보내는 운행 원장(웹훅)을 받아, 회사 관리자 화면으로 보여주는 시연용 서버입니다.
파이썬 표준 라이브러리만 쓰므로 설치할 것이 없고, Python 3.9 이상이면 macOS, Windows, Linux에서 그대로 실행됩니다.

## 실행

```
python3 fleet_console.py --port 8787 --bind 127.0.0.1 --data ./fleet-data
```

- 관리자 화면: http://127.0.0.1:8787/ (2초마다 자동 갱신)
- 안드로이드 에뮬레이터가 보낼 주소: `http://10.0.2.2:8787/hook` (에뮬레이터의 10.0.2.2는 이 노트북의 127.0.0.1입니다)
- 실제 단말로 시연하려면 `--bind 0.0.0.0`을 쓰되, 인증이 없으므로 시연하는 동안만 켜 두세요.
- `--data` 폴더에는 받은 원장과 운행기록부 파일이 쌓입니다. 시연 기록이므로 저장소에 올리지 마세요.

## 주소

| 주소 | 설명 |
| --- | --- |
| `POST /hook` | 원장 항목(`ledger_entry`)과 운행기록부(`logbook_archive`) 수신. `Idempotency-Key` 헤더가 같으면 한 번만 반영 |
| `GET /` | 관리자 화면 |
| `GET /api/state` | 화면이 쓰는 JSON (차량별 상태, 이번 달·올해 집계, 최근 운행 30건, 보관 파일, 알림) |
| `GET /archives/<파일>` | 보관된 운행기록부 내려받기 |
| `GET /healthz` | 살아 있는지 확인 (`ok`) |

## 검증 규칙

- 항목마다 해시를 다시 계산합니다. 어긋나면 **변조 의심**.
- 번호(seq)가 건너뛰면 **누락 있음**, 같은 번호에 다른 내용이 오면 **변조 의심**.
- 업무 사용 비율 = (출퇴근 + 일반 업무) ÷ 전체 주행거리. 업무 km는 출퇴근과 일반 업무의 합입니다.
- 서버를 껐다 켜도 `--data`의 기록을 다시 읽어 같은 화면을 복원합니다.

## 메모리 한도 (코드 상단 상수)

차량 200대, 차량당 원장 50,000건(최신 유지), 운행기록부 100개(오래된 것부터 삭제), 요청 본문 15MB(초과 시 413), Idempotency-Key 차량당 5,000개.
