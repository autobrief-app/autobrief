# 시연 절차 (본선 PT와 시연 영상 녹화 공용)

화면 두 개로 진행합니다. 왼쪽은 Pleos Connect 에뮬레이터(오토브리프), 오른쪽은 회사 관리자 화면(브라우저)입니다.
차는 가상 콘솔 API로 움직이고(`demo/director.py`), 장면마다 발표자가 Enter를 눌러 넘깁니다.
숫자와 이름은 모두 가상 예시입니다(가상 회사, 가상 인물, 공공 장소 좌표를 쓴 가상 장소).

## 준비물

- 노트북: Apple 칩 Mac 또는 외장 그래픽카드(노트북 RTX 3060급 이상) Windows/Linux. Pleos 공식 안내상 그래픽카드가 필수입니다.
- 파이썬 3.9 이상, Android Studio(에뮬레이터와 platform-tools 설치), 이 저장소, `apk/`의 릴리스 APK
- 인터넷이 없어도 됩니다. 장소 인식에 쓰는 위치는 시연 대본이 에뮬레이터 GPS로 넣습니다. 앱은 내비 위치를 먼저 쓰고,
  내비가 그 위치를 따라가지 않으면(에뮬레이터 이미지) 차량 GPS(설치 때 위치 권한 허용)로 집, 회사, 거래처를 알아봅니다.
  지도는 앱이 위치를 확인하는 동안에만 잠깐 보이고, 길 안내는 쓰지 않습니다.

## 전날 준비 (약 30분, 처음 한 번은 이미지 4GB 내려받기 포함)

1. `python3 demo/setup_emulator.py --apk apk/<배포 APK>` — 이미지 설치, 가상 기기 생성, 콜드 부팅, 앱 설치, 가상 콘솔 연결
2. `python3 tools/fleet-console/fleet_console.py --data ./fleet-data` — 관리자 화면, 브라우저에서 `http://127.0.0.1:8787/`
3. 앱 설정에서 시연 모드 켜기 → '가상 예시 이력 불러오기' → 시연 모드 설정의 보내기 주소에 `http://10.0.2.2:8787/hook`을
   넣고 저장. 설정은 실제 기록과 시연 공간에 따로 저장되므로 이 순서로 합니다. 보내기 주소를 처음 저장하면 그때까지의
   원장 전체가 관리자 화면으로 갑니다(관리자 화면에 1월부터의 원장이 들어오고 '정상'과 검증 코드가 보이면 준비 끝)
4. 리허설: `python3 demo/director.py --scenario all --mode step` 을 처음부터 끝까지 두 번.
   대본 7장면 전체를 사람 없이 한 번에 점검하려면(관리자 화면이 켜진 채로):
   `python3 demo/rehearsal.py --out rehearsal-out --fleet-data ./fleet-data`
   장면마다 화면의 글자를 찾아 실제로 누르고 PASS/FAIL을 냅니다. 실패한 장면은 `rehearsal-out`에 스크린샷과 화면 구조가
   남습니다. 7번(Gleo 요청)은 디버그 APK에서만 재현됩니다. 리허설은 운행 3건, 정정, 위조 기록을 실제로 남기므로 끝나면
   '위변조 시연' 끝의 방법으로 처음 상태로 되돌립니다.

## 선택 장면 (대본 7장면 뒤, 시간이 남을 때)

위 7장면과 CI 검증은 그대로입니다. 아래 두 장면은 `--scenario all`에 들어가지 않고, 따로 부를 때만 돕니다. 둘 다 디버그 APK의
디버그 신호를 씁니다(가족 운행은 Gleo 요청을 디버그 신호로 재현한 것이고 음성이 아닙니다). 화면에서 직접 해도 됩니다.

| 장면 | 하는 일 | 화면에서 보일 것 |
|---|---|---|
| 8. 가족 운행 | `python3 demo/director.py --scenario family --mode step`: 주차 중에 가족 운행을 켜고(화면에서는 오늘 화면의 "다음 운행은 가족 운행" 스위치) 12 km 운행, P | 위쪽 표시 "위치 읽지 않음 (가족 운행)", 주행 화면 "가족 운행 중 (위치 기록 안 함)" → "비업무로 기록했습니다", 운행 목록과 관리자 화면에 "가족 운행 (위치 기록 안 함)", 장소 없음. 스위치는 저절로 꺼짐 |
| 9. 유류비 정산 | `python3 demo/director.py --scenario fuel --mode step`: 내 차 모드, 유가 1,650원/L, 연비 12.1km/L(직접 입력)를 넣고(화면에서는 설정의 차량 구분, 유가, 연비 직접 입력) 회사에서 가상상사까지 11 km | 오늘 화면의 절세 카드 자리에 유류비 정산 카드: "이번 달 업무 …km, 평균 연비 12.1km/L(100km당 8.26L, 직접 입력), 유가 1,650원/L, 정산 …원"(금액은 100km당 리터로 계산). 에뮬레이터는 누적 연비를 주지 않으므로(10월 28일 시험) 출처가 '직접 입력'으로 나옴. 연비를 주는 차에서는 '차량 누적 연비' |

9번 뒤 운행기록부 탭에서 '이번 달'을 골라 '지금 보내기'를 누르면 엑셀에 '유류비 정산' 시트가 붙고, 관리자 화면의 그 차 아래에
"유류비 정산 N원" 한 줄이 나옵니다. 에뮬레이터가 알려 주는 연비는 앱 로그의 `FUEL_ECONOMY` 줄에서 확인합니다
(`adb logcat -s AutoBriefLog`). 시연 공간의 설정을 처음으로 되돌리려면 `--es cmd fuel --es mode company`를 보냅니다.

엑셀을 노트북으로 가져오기: 앱의 '지금 보내기'가 엑셀을 차에 저장하고 관리자 화면으로 보냅니다. 관리자 화면의
'운행기록부 보관함'에서 파일 이름을 누르면 내려받아집니다. `adb pull`로는 가져올 수 없습니다. Pleos 이미지에서 앱은
Android 사용자 10으로 실행되고, adb와 `run-as` 모두 그 저장소를 읽지 못합니다(Permission denied, 2026-10-27 리허설에서 확인).

음성비서(Gleo)가 에뮬레이터에서 응답하지 않으면 그렇다고 말하고 화면 기능으로 진행합니다. 앱의 음성 수신기는 Gleo만 가진
권한이 있어야 열리므로 adb로 직접 흉내 낼 수 없습니다. 디버그 APK로 리허설할 때만 같은 요청을 이렇게 보낼 수 있습니다:
`adb shell am broadcast -a app.autobrief.car.debug.DEMO -p app.autobrief.car --es cmd gleo --es function GET_LOGBOOK_STATUS --es params '{"period":"THIS_MONTH"}'`
(응답은 `adb logcat -s AutoBriefLog`의 `GLEO_REPLY` 줄)

## 위변조 시연

관리자 화면은 받은 원장 한 줄마다 해시를 다시 계산하고 앞 줄과 이어지는지 봅니다. 시연에서는 노트북에서
"비업무 운행을 일반 업무로 바꾼 위조 기록"을 한 줄 보내 관리자 화면이 '변조 의심'으로 바뀌는 것을 보여 줍니다.
위조 기록은 차의 기록을 바꾸지 않습니다(노트북에서 관리자 화면으로만 보냄).

```
python3 tools/fleet-console/forge_demo.py --data ./fleet-data
```

목적을 처음 '비업무'로 정한 기록 가운데 가장 최근 것을 '일반 업무'로 바꾸고 해시를 다시 계산해 보냅니다. 관리자 화면은 같은 순번에 다른 내용이
도착했다고 보고 '변조 의심'과 함께 이미 받은 순번에 다른 기록이 왔다는 알림을 띄웁니다(가상 예시 원장으로 확인).
집계 위에는 빨간 알림 띠가 뜨고, 그 운행 줄에는 '변조 시도' 표시가 붙습니다. 회사 사본은 처음 받은 기록 그대로입니다.
시연이 끝나면 관리자 화면 서버를 끄고 `fleet-data` 폴더를 지운 뒤 다시 켜고, 앱의 시연 모드 설정에서
'가상 예시 이력 불러오기'를 다시 누르면 '정상'으로 돌아갑니다.

## 문제가 생기면

- 가상 콘솔이 응답하지 않음: `adb forward tcp:8088 tcp:8088` 다시 실행
- 자동 분류가 안 됨(위치가 안 들어옴): 화면에서 목적을 고르는 흐름으로 그대로 진행합니다. 기록 자체(계기판 값)는 위치와 무관합니다.
- 앱이 닫힘: 다시 열면 됩니다. 기록은 저장되어 있고, 열려 있던 운행은 다음 P에서 이어집니다.
- '지금 보내기'(또는 '엑셀 만들기') 뒤 '만드는 중…'이 이어짐: 앱이 엑셀을 화면과 따로 만드는 중입니다. 그동안 두 버튼은
  꺼져 있고 화면은 그대로 움직입니다. 다 되면 '저장하고 전송을 시작했습니다: 파일 이름'이 나옵니다. 전날 시연 PC에서 한 번
  눌러 걸리는 시간을 봐 둡니다.
- 에뮬레이터가 느림: 대본을 `--km-interval 2` 로 천천히 돌립니다.
- 화면이 검은 채로 부팅이 끝나지 않음: 하드웨어 가속(Apple 칩의 가상화, 다른 PC의 KVM이나 Windows 가속 기능)이 없는 PC에서
  생깁니다. 소프트웨어로만 실행하면 차량 서비스가 끝내 올라오지 않아 앱을 열 수 없습니다(2026-10-25 가속 없는 서버에서 확인).
  가속이 되는 노트북에서 실행하세요.
