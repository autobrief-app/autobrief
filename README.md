# 오토브리프 (AutoBrief)

기어가 P를 벗어날 때와 P로 돌아올 때마다 계기판 누적거리로 국세청 서식 업무용승용차 운행기록부를 스스로 쓰는 Pleos Connect 앱입니다.
휴대폰도, GPS 이동 경로 저장도 없이 차가 직접 기록하고, 한 번 쓴 기록은 고친 내역까지 남는 증빙으로 보관합니다.

## 1. 앱 이름과 한 줄 소개

- 앱 이름: 오토브리프 (AutoBrief), 패키지 `app.autobrief.car`, 버전 2.0.0
- 한 줄 소개: 기어를 P에 두는 순간 계기판 거리로 운행기록부 한 줄이 생기고, 출퇴근과 거래처 방문은 목적까지 자동으로 적히는 차량 전용 운행기록부

| 기능 | 하는 일 | 쓰는 Pleos/AAOS API |
|---|---|---|
| 운행마다 자동 기록 | 기어가 P를 벗어날 때와 P로 돌아올 때 계기판 누적거리(⑤⑥)를 읽어 한 줄을 씁니다. 앱이 못 본 사이 계기판이 0.05 km 넘게 움직였으면 `미기록 구간(비업무)`으로 따로 남깁니다. | Vehicle `Odometer`, `Gear`, `CarInfo`(차대번호) |
| 장소로 목적 자동 분류 | 집→회사, 회사→집은 출퇴근(⑧), 등록한 거래처 도착은 일반 업무(⑨)로 적습니다. 그 밖의 운행은 정차 후 화면에서 묻고(출퇴근, 일반 업무, 비업무), 음성으로도 정할 수 있습니다. 위치는 내비 위치를 먼저 쓰고, 내비 위치가 30초보다 오래됐거나 차량 GPS와 다른 장소를 가리키면 차량 GPS 위치(위치 권한을 허용한 경우)를 씁니다. 위치는 장소를 알아보는 데만 쓰고 기록에는 장소 이름만 남깁니다. | NaviHelper 즐겨찾기(HOME/OFFICE), 현재 위치, 목적지와 예상 통행료. Android 위치(차량 GPS, 선택) |
| 고친 내역이 남는 기록 원장 | 운행 한 줄과 목적 지정, 수정이 모두 해시로 이어진 원장에 쌓입니다. 이미 정한 목적을 고치려면 이유(경유지가 있었어요, 개인 용무를 겸했어요, 사용자가 달라요, 기타 정정)를 골라야 하고, 엑셀의 '검증 기록' 시트와 회사 서버 사본(보내기 주소를 넣은 경우)으로 대조할 수 있습니다. | (앱 내부) SHA-256 해시 체인 |
| 가족 운행 | 주말에 가족을 태우고 갈 때 운행 전이나 운행 중에 켭니다. 그 운행이 끝날 때까지 앱은 위치를 읽지 않고(내비 위치를 묻지 않고 차량 GPS도 끔), 주차하면 거리만 비업무로 한 줄 남깁니다(⑩비고 "개인 운행(위치 기록 안 함)", 장소 없음). 운행이 끝나면 저절로 꺼지고, 나중에 화면에서 이유를 골라 출퇴근이나 일반 업무로 고칠 수 있습니다. | 오늘 화면의 스위치 "다음 운행은 가족 운행", Gleo `LOG_TRIP_PURPOSE`(FAMILY) |
| 유류비 정산 (내 차) | 직원이 자기 차를 업무에 쓸 때, 한 달의 업무 거리에 차량이 알려 주는 평균 연비와 유가를 곱해 유류비를 계산합니다(10원 단위 반올림). 설정의 차량 구분에서 '내 차(업무에 사용)'를 고르면 오늘 화면과 운행기록부 화면에 절세 계기판 대신 유류비 정산 카드가 나오고, 엑셀에 '유류비 정산' 시트가 붙습니다. 유가는 오피넷 지역 평균가를 직접 넣습니다. | Vehicle `Fuel` 누적 연비(L/100km), `EvBattery` 누적 전비(전기차 구분용) |
| 음성 (Gleo) | "방금 운행 업무로 기록해 줘", "가족 운행 켜 줘", "이번 달 업무 비율 알려줘"(내 차 모드면 유류비 정산 금액도, 미기록 구간이 있으면 그 건수와 거리도), "지난달 운행기록부 보내줘" | Gleo Interface 함수 3개 |
| 국세청 서식 엑셀 | 월, 반기, 사업연도별 「업무용승용차 운행기록 방법에 관한 고시」 별지 서식 항목(③~⑬) + 검증 기록 시트. 새 달 첫 시동 때 지난달 기록부를 자동으로 만들고, 보내기 주소를 넣은 경우 그 주소로 보냅니다. | (앱 내부) OOXML 작성 |
| 절세 계기판 | 법인세법 시행령 §50의2 기준으로 운행기록부가 있을 때와 없을 때 비용 인정액 차이와 세금 효과를 보여 줍니다(일반 법인 기준: 1,500만 원 한도, 감가상각비 연 800만 원 한도, 법인세율). | (앱 내부) |
| 회사 관리자 화면 | 보내기 주소를 넣으면 기록이 생길 때마다 원장 한 줄과 해시가 그 주소(회사 서버)로 가고, 관리자 화면이 차량별 업무 비율과 위변조 여부를 보여 줍니다. | 웹훅(HTTPS) + `tools/fleet-console` |
| 주행 중 화면 | 주행 중에는 큰 글씨 상태만 보이고 입력 화면을 띄우지 않습니다. | AAOS `CarUxRestrictions` |

외부 앱이 할 수 없어서 하지 않는 것: 하이패스 실제 결제 금액 읽기(통행료는 내비가 계산한 경로 예상값만 비고에 적음), 순정 화면 변경, 문자 발송.

## 2. 실행 방법

1. Android Studio(Gradle 8.7, JDK 17)에서 이 저장소를 엽니다. Pleos SDK는 `settings.gradle.kts`의 공개 저장소
   `https://nexus-playground.pleos.ai/repository/maven-releases/`에서 받습니다.
2. 에뮬레이터 준비는 한 줄로 됩니다(Mac Apple 칩, Windows, Linux 공통, 파이썬 3.9 이상):
   `python3 demo/setup_emulator.py --apk apk/<배포 APK>` (Pleos Connect v2.1.0 이미지 내려받기, 가상 기기 생성, 콜드 부팅, 설치, 가상 콘솔 열기)
   - 공식 안내대로 외장 그래픽카드(노트북 RTX 3060급 이상) 또는 Apple 칩 Mac이 필요합니다.
3. 앱을 열고 '가상 예시로 둘러보기'를 누르면 실제 기록과 분리된 시연 공간에 가상 회사의 2026년 1월 2일부터 어제까지의 기록이 들어옵니다.
4. 차를 움직이는 방법: 가상 콘솔(`http://127.0.0.1:8088/`)에서 기어와 계기판을 바꾸거나, 시연 대본을 돌립니다:
   `python3 demo/director.py --scenario all --mode step`
5. 회사 관리자 화면: `python3 tools/fleet-console/fleet_console.py` 후 브라우저에서 `http://127.0.0.1:8787/`,
   앱 설정의 보내기 주소에 `http://10.0.2.2:8787/hook` (에뮬레이터에서 노트북을 가리키는 주소).
   설정은 실제 기록과 시연 공간에 따로 저장되므로, 시연 때는 시연 모드를 켠 뒤 넣습니다(순서는 `docs/DEMO.md`).

시연 순서와 확인할 화면은 `docs/DEMO.md`에 있습니다.

## 3. 테스트 환경과 설정

- 단위 테스트: `./gradlew testDebugUnitTest` (기록 엔진, 해시 원장 위변조 감지, 장소 자동 분류, 절세 계산,
  엑셀 형식, Gleo 스키마, 시연 공간 분리, 월말 자동 마감, Robolectric 실행 시험, 화면 캡처)
- 화면 캡처: `app/build/outputs/roborazzi/*.png` (2560x1440 차량 화면과 세로형 화면, 밤과 낮 테마)
- 가상 예시 데이터: `SampleScenarioTest`가 앱 기록 엔진 형식으로 만든 가상 회사의 2026년 1월 2일~10월 23일 기록
  (10월 23일 운행 2건은 기어, 계기판, 내비 신호를 재생)을 `app/build/sample/`에 엑셀과 요약으로 씁니다(`docs/samples`에 복사본). 실제 차량, 법인, 인물이 아닙니다.
- 에뮬레이터 종단 시험: `demo/director.py --verify`가 가상 콘솔로 기어와 계기판을 움직이고 앱 로그(`AutoBriefLog`)에서
  운행 기록과 자동 분류 결과를 확인합니다.
- 릴리스 서명 키와 비밀번호는 저장소에 없습니다. 빌드할 때 `AUTOBRIEF_KEYSTORE_PATH`, `AUTOBRIEF_KEYSTORE_PASSWORD`
  환경 변수로 넘깁니다.

## 4. APK 위치

- `apk/` 폴더의 릴리스 APK (공모전 규칙 `팀명_앱이름_release.apk`)

## 권한

`pleos.car.permission.CAR_DRIVE`(계기판, 기어), `CAR_INFO`(차대번호), `CAR_ENERGY`(누적 연비, 유류비 정산. 보호 수준 normal이라 설치할 때 허용됨),
`NAVI_ROUTE`(즐겨찾기, 현재 위치, 목적지),
인터넷(보내기 주소), 포그라운드 서비스(화면을 열지 않아도 기록, 특수 용도와 위치 유형), 부팅 완료 수신,
위치(`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, 선택).

- 실행 중 동의를 받는 권한은 위치 하나입니다. 첫 실행 때 이유("내비가 위치를 주지 못할 때 차량 GPS로 집, 회사,
  거래처를 알아보기 위해서")를 보여 주고 한 번만 묻습니다. 거절해도 앱은 내비 위치만으로 그대로 동작합니다.
- 백그라운드 위치 권한은 요청하지 않습니다. 차량 GPS는 기록 서비스가 포그라운드 서비스(위치 유형)로 도는 동안에만 받습니다.

## 개인정보와 위치정보

- 이동 경로를 저장하지 않습니다. 내비 위치는 운행 중 6초마다, 주차 중 1분마다 묻고, 위치 권한을 허용했다면 차량 GPS
  위치를 5초마다 받습니다. 어느 쪽이든 메모리에서 등록 장소와 비교하고 버립니다. 저장하는 좌표는 사용자가 등록한
  장소뿐이고, 운행기록에는 "집", "회사", 거래처 이름만 남습니다. 화면 위쪽 표시는 지금 쓰는 위치가 내비인지 차량 GPS인지
  알려 줍니다.
- 가족 운행을 켜면 그 운행이 끝날 때까지 내비 위치를 묻지 않고 차량 GPS 수신도 멈춥니다. 그래도 들어오는 위치는 쓰지도
  남기지도 않고 버리며, 켜는 순간 메모리에 있던 마지막 위치도 지웁니다. 운행 중에 켜면 그 운행의 출발 장소도 버립니다.
  가족 운행은 이 앱의 기록만 다룹니다. 차의 기본 내비게이션은 최근 목적지 같은 자체 기록을 따로 남기며, 이 앱이 그것을 끄거나
  지울 수는 없습니다.
- 기록은 차량 안 앱 저장소에 있고, 보내기 주소를 넣었을 때만 그 주소(회사 서버)로 원장과 엑셀이 갑니다.
- 관리자 PIN을 정한 뒤에는 보내기 주소와 PIN을 바꿀 때 현재 PIN이 필요합니다. 목적을 고치면 고른 이유와 이전 목적이 원장에 남습니다.
- 시연 모드는 실제 기록과 다른 저장 공간(설정 포함)을 쓰고, 시연 중 0.05 km 넘게 움직인 거리는 실제 기록부에 미기록 구간(비업무)으로 남습니다.

## 유류비 정산의 계산과 한계

- 달마다: 업무 거리(일반 업무 km, '출퇴근 포함'을 고르면 출퇴근 km도) × 연비(L/100km) ÷ 100 × 유가(원/L), 10원 단위 반올림.
  연비는 차량이 알려 주는 누적 연비(L/100km, 0보다 크고 50보다 작은 값만)를 소수 둘째 자리로 맞춰 쓰고, 화면에는 km/L로도
  보여 줍니다. 앱은 시작할 때와 운행이 끝날 때마다 화면 스레드 밖에서 연비를 읽고, 받은 값을 로그에 한 줄(`FUEL_ECONOMY`) 남깁니다.
- 차량이 연비를 알려 주지 않으면 카드에 "차량 연비 값을 받지 못했습니다"라고 쓰고, 설정의 '연비 직접 입력(km/L)'으로 계산합니다.
  그때 출처는 '직접 입력'으로 적습니다. 정해 둔 숫자로 대신 채우지 않습니다.
- Pleos 에뮬레이터(Connect v2.1.0)는 누적 연비를 주지 않습니다(2026-10-28 종단 시험 로그: `CUMULATIVE_FUEL_ECONOMY`
  property ID is not in carProperty, 전비도 같음). 그래서 시연 장면은 연비 12.1km/L를 직접 입력으로 넣습니다.
- 전기차: 차량이 전비(km/kWh)만 알려 주면 카드에 "전기차 정산은 다음 버전"이라고 나옵니다. 충전 요금(원/kWh)으로 정산하는
  기능은 이번 버전에 없습니다. Vehicle SDK 2.3.2에는 차의 연료 종류를 알려 주는 API가 없어, 연비 없이 전비만 오는 차를 전기차로 봅니다.
- 엑셀의 '유류비 정산' 시트와 월 마감 금액은 그 파일을 만든 날 앱에 있던 연비와 유가로 계산합니다(시트 아래에 기준을 적음).
